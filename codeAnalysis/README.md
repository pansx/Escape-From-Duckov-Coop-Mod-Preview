## 项目概述

**Escape From Duckov Coop Mod** 是一个为单人游戏《逃离鸭科夫》(Escape From Duckov) 开发的联机合作模组。该项目使用运行时代码注入技术（HarmonyLib），在不修改游戏原始文件的情况下，实现了完整的多人联机功能。

### 项目背景

《逃离鸭科夫》是一款单人生存射击游戏，玩家需要在充满敌人的环境中收集物资、完成任务并逃离。本模组的目标是让玩家能够与朋友一起体验这款游戏，共同面对挑战。

### 核心功能

- **多人游戏同步**：支持2-16人联机，实时同步玩家位置、动作、装备

- **AI行为同步**：主机权威的AI管理，确保所有玩家看到相同的敌人行为

- **战利品共享**：同步战利品箱内容，防止重复拾取

- **完整战斗系统**：同步射击、近战、投掷物、伤害计算

- **场景切换**：支持投票切换场景，同步加载进度

- **死亡观战**：死亡后可观战其他玩家

- **多种联机方式**：支持局域网直连和Steam P2P联机

### 技术栈

- **开发语言**：C# (.NET Standard 2.1)

- **游戏引擎**：Unity 2021.3.x

- **网络库**：LiteNetLib (UDP传输)

- **Steam集成**：Steamworks.NET (P2P网络)

- **代码注入**：HarmonyLib 2.x (运行时补丁)

- **异步框架**：UniTask (高性能异步)

### 项目统计

- **总目录数**：28个目录

- **总文件数**：110个C#源代码文件

- **代码行数**：约25,000行

- **主要模块**：3个核心模块（Main、Net、Patch）

- **子模块数量**：20个子模块（深度2）

- **辅助模块**：4个（Utils、SyncData、NetTag、RootHelpers）

- **补丁数量**：26个Harmony补丁文件

- **网络操作码**：100+个网络消息类型

- **最大目录深度**：2层（不含根目录）

### 分层架构详解

项目采用经典的分层架构设计，从下到上分为五个主要层次：

#### 1. 基础设施层（Infrastructure Layer）

**组成**：Unity引擎、第三方库、游戏原始代码

**职责**：

- 提供运行时环境和基础API

- 提供物理、渲染、动画等核心功能

- 提供网络传输和Steam集成能力

**关键组件**：

- Unity Engine（游戏引擎）

- LiteNetLib（UDP网络库）

- Steamworks.NET（Steam API）

- HarmonyLib（代码注入框架）

- 游戏原始代码（TeamSoda.Duckov.Core.dll）

#### 2. 代码注入层（Patch Layer）

**组成**：Patch模块及其6个子模块

**职责**：

- 拦截游戏原始方法的执行

- 注入网络同步逻辑

- 实现客户端-服务器架构

- 防止状态不一致和作弊

**关键特性**：

- 非侵入式修改（不修改游戏文件）

- 运行时动态补丁

- 支持Prefix/Postfix/Transpiler三种补丁类型

- 优先级控制和条件执行

**交互方式**：

- 向上：触发Main模块的业务逻辑

- 向下：拦截游戏原始代码的调用

#### 3. 网络通信层（Network Layer）

**组成**：Net模块及其2个子模块

**职责**：

- 提供高效的网络传输服务

- 实现数据压缩和优化

- 提供插值和平滑算法

- 管理网络质量和统计

**关键特性**：

- 智能传输选择（根据Op自动选择传输方式）

- 多通道系统（避免队头阻塞）

- Fika架构插值系统（平滑位置和动画）

- 对象池优化（减少GC压力）

- Steam P2P透明代理

**交互方式**：

- 向上：为Main模块提供网络API

- 向下：使用LiteNetLib和Steam API进行传输

- 横向：与Patch模块协同处理网络事件

#### 4. 业务逻辑层（Business Logic Layer）

**组成**：Main模块及其12个子模块

**职责**：

- 实现联机游戏的核心业务逻辑

- 协调各个子系统的工作

- 管理玩家、AI、物品、场景等游戏对象

- 处理网络消息和事件

**关键特性**：

- 服务器权威架构（防止作弊）

- 去抖和节流控制（优化性能）

- 异步处理（避免阻塞）

- 完善的错误处理和降级策略

**交互方式**：

- 向上：为UI层提供数据和接口

- 向下：使用Net层的网络服务

- 横向：与Patch层协同处理游戏事件

#### 5. 表现层（Presentation Layer）

**组成**：UI模块、本地化模块、特效管理器

**职责**：

- 提供用户界面和交互

- 显示游戏状态和信息

- 播放特效和音效

- 支持多语言

**关键特性**：

- 联机菜单和房间浏览

- 玩家列表和状态显示

- 投票界面和场景选择

- 多语言支持（5种语言）

**交互方式**：

- 向下：调用Main层的业务逻辑

- 横向：监听游戏事件和网络事件

### 模块职责

#### 1. Main模块 - 核心业务逻辑层

**职责**：实现联机游戏的核心业务逻辑，协调各个子系统

**核心类**：- `COOPManager`: 中央管理器，初始化所有子系统

- `NetService`: 网络服务核心，管理连接和传输

- `Op`: 网络操作码定义（100+个消息类型）

- `CoopTool`: 通用工具函数集

**子模块**：- **AI**：AI角色同步（位置、动画、装备、生命值）

- **ClientService**：客户端服务（状态上报、数据接收）

- **Health**：生命值系统（主机权威的伤害结算）

- **HostService**：主机服务（玩家管理、权威数据下发）

- **Item**：物品系统（掉落、拾取、容器交互）

- **Loader**：模组加载器（初始化入口）

- **Localization**：多语言支持

- **LocalPlayer**：本地玩家管理（输入、状态、同步）

- **SceneService**：场景服务（切换、投票、同步加载）

- **UI**：用户界面（主菜单、玩家列表、投票界面）

- **Weapon**：武器系统（射击、换弹、武器切换）

- **WeatherAndTime**：天气和时间同步

**详细文档**：[Main/README.md](duckovAPI/Main/README.md)


#### 2. Net模块 - 网络通信层

**职责**：提供高效的网络传输、数据压缩、插值优化和质量监控

**核心类**：- `NetInterpolator`: Fika架构的高级插值系统

- `NetworkExtensions`: 智能发送扩展（自动选择传输方式）

- `OpPriority`: 操作码优先级映射

- `PacketPriority`: 数据包优先级系统

- `NetPacketPool`: 数据包对象池（减少GC）

- `NetAiFollower`: AI动画跟随器

- `LocalHitKillFx`: 本地命中特效

**子模块**：- **NetPack**：网络数据打包工具（位置压缩、方向压缩、伤害打包）

- **Steam**：Steam P2P网络实现（Lobby管理、端点映射、P2P连接）

**关键技术**：- 数据压缩：Vector3压缩50%，Quaternion压缩67%

- 多通道系统：4个通道避免队头阻塞

- 智能传输：根据Op自动选择Reliable/Unreliable

- Fika插值：时间轴系统、动态延迟、追赶/减速机制

- 网络质量监控：实时统计延迟、抖动、质量评分

**详细文档**：[Net/README.md](duckovAPI/Net/README.md)

#### 3. Patch模块 - 代码注入层

**职责**：使用HarmonyLib对游戏原始代码进行运行时修改

**核心技术**：- **Prefix补丁**：在原方法执行前拦截，可跳过原方法

- **Postfix补丁**：在原方法执行后插入逻辑

- **Transpiler补丁**：修改IL代码实现复杂逻辑

**子模块**：- **Character**：角色系统补丁（生成、移动、动画、装备）

- **InventoryAndLootBox**：背包和战利品箱补丁

- **Item**：物品系统补丁（生成、销毁、属性同步）

- **Projectile**：投射物补丁（子弹、手榴弹、命中检测）

- **Scene**：场景补丁（加载、对象同步、环境交互）

- **SteamP2P**：Steam P2P补丁（Socket拦截、数据包重定向）

**补丁策略**：- 客户端预测：立即执行操作，等待服务器确认

- 服务器权威：关键操作由主机决定

- 状态同步：定期快照 + 增量更新

- 冲突解决：服务器时间戳作为权威

**详细文档**：[Patch/README.md](duckovAPI/Patch/README.md)

#### 4. 辅助模块

**Utils模块**：- `ExponentialMovingAverage`: 指数移动平均（网络质量监控）

- `SceneTriggerResetter`: 场景触发器重置工具

**SyncData模块**：- `EquipmentSyncData`: 装备同步数据结构

- `WeaponSyncData`: 武器同步数据结构

**NetTag模块**：- `NetDestructibleTag`: 可破坏物网络标记

- `NetDropTag`: 掉落物品网络标记

- `NetGrenadeTag`: 手榴弹网络标记

**RootHelpers模块**：- `AnimParamInterpolator`: 动画参数插值器

- `AutoRequestHealthBar`: 自动请求血条组件

- `BuffLateBinder`: Buff延迟绑定器

- `DeferedRunner`: 延迟执行器

- `HoldVisualBinder`: 手持物品视觉绑定器

- `HostForceHealthBar`: 主机强制血条组件

#### 模块间交互方式

**Main ↔ Net 交互**：

- Main调用Net的SendSmart()发送数据

- Net通过回调通知Main接收到数据

- Main使用Net的插值器平滑远程对象

**Main ↔ Patch 交互**：

- Patch拦截游戏事件，调用Main的处理方法

- Main注册回调，Patch在适当时机触发

- 双向通信：Patch→Main（事件通知），Main→Patch（状态查询）

**Net ↔ Patch 交互**：

- Patch拦截Socket调用，重定向到Steam P2P

- Net提供网络统计，Patch用于优化

- 间接交互：通过Main模块协调

**模块间消息流**：

```

用户操作 → Patch拦截 → Main处理 → Net发送 → 网络传输
                                              ↓
远程接收 ← Main应用 ← Net接收 ← 网络传输 ←────┘

```

### 模块间交互模式

#### 1. 请求-响应模式（Request-Response Pattern）

**适用场景**：需要确认的操作（如物品拾取、伤害结算）

**交互流程**：

```

客户端                主机
  │                    │
  ├─ 发送请求 ────────▶│
  │   (REQUEST)        │
  │                    ├─ 验证请求
  │                    │
  │                    ├─ 执行操作
  │                    │
  │◀──── 发送响应 ─────┤
  │   (RESPONSE)       │
  │                    │
  ├─ 应用结果          │
  │                    │

```

**示例**：

- 物品拾取：ITEM_PICKUP_REQUEST → ITEM_DESPAWN

- 伤害结算：MELEE_HIT_REPORT → AUTH_HEALTH_SYNC

- 场景投票：SCENE_VOTE_REQ → SCENE_VOTE_START

#### 2. 广播模式（Broadcast Pattern）

**适用场景**：需要通知所有客户端的事件

**交互流程**：

```

主机                客户端A    客户端B    客户端C
  │                    │          │          │
  ├─ 广播事件 ────────▶│          │          │
  │   (BROADCAST)      │          │          │
  ├────────────────────┼─────────▶│          │
  │                    │          │          │
  ├────────────────────┼──────────┼─────────▶│
  │                    │          │          │
  │                    ├─ 应用    ├─ 应用    ├─ 应用

```

**示例**：

- 玩家加入：REMOTE_CREATE（广播给所有人）

- AI生成：AI_SEED_SNAPSHOT（广播AI种子）

- 场景切换：SCENE_BEGIN_LOAD（广播加载命令）

#### 3. 转发模式（Relay Pattern）

**适用场景**：客户端间接通信

**交互流程**：

```

客户端A            主机            客户端B/C
  │                  │                  │
  ├─ 发送状态 ──────▶│                  │
  │   (UPDATE)       │                  │
  │                  ├─ 转发 ──────────▶│
  │                  │   (FORWARD)      │
  │                  │                  ├─ 应用

```

**示例**：

- 位置更新：客户端A → 主机 → 其他客户端

- 动画同步：客户端A → 主机 → 其他客户端

- 装备更新：客户端A → 主机 → 其他客户端

#### 4. 快照同步模式（Snapshot Pattern）

**适用场景**：定期同步完整状态

**交互流程**：

```

主机                客户端
  │                    │
  ├─ 定期快照 ────────▶│
  │   (SNAPSHOT)       │
  │                    ├─ 完全替换状态
  │                    │
  ├─ 定期快照 ────────▶│
  │   (SNAPSHOT)       │
  │                    ├─ 完全替换状态

```

**示例**：

- AI变换快照：AI_TRANSFORM_SNAPSHOT（10Hz）

- AI动画快照：AI_ANIM_SNAPSHOT（10Hz）

- AI装备快照：AI_LOADOUT_SNAPSHOT（事件驱动）

#### 5. 增量同步模式（Delta Pattern）

**适用场景**：高频更新，只发送变化

**交互流程**：

```

客户端              主机
  │                  │
  ├─ 增量更新 ──────▶│
  │   (DELTA)        │
  │                  ├─ 累积变化
  │                  │
  ├─ 增量更新 ──────▶│
  │   (DELTA)        │
  │                  ├─ 累积变化

```

**示例**：

- 位置更新：只发送位置和旋转（不发送其他状态）

- 动画更新：只发送变化的动画参数

- 血量更新：只发送当前血量（不发送最大血量）

#### 6. 事件驱动模式（Event-Driven Pattern）

**适用场景**：一次性事件

**交互流程**：

```

触发源              监听者
  │                  │
  ├─ 触发事件 ──────▶│
  │   (EVENT)        │
  │                  ├─ 执行回调
  │                  │
  │                  ├─ 处理完成

```

**示例**：

- 射击事件：FIRE_EVENT

- 手雷爆炸：GRENADE_EXPLODE

- 玩家死亡：PLAYER_DEAD_TREE

### 状态同步机制

#### 1. 快照同步（Snapshot Synchronization）

**用于**：AI状态、玩家装备、场景对象

**特点**：- 定期发送完整状态快照（20-50Hz）

- 包含所有必要信息

- 接收端直接应用，无需累积

**示例**：```csharp
// AI变换快照
public void Server_BroadcastAiTransforms()
{
    var writer = NetPacketPool.GetWriter();
    writer.Put((byte)Op.AI_TRANSFORM_SNAPSHOT);
    writer.Put(aiCount);

    foreach (var ai in allAIs)
    {
        writer.Put(ai.id);
        writer.PutV3cm(ai.position);    // 压缩位置
        writer.PutDir(ai.forward);      // 压缩方向
    }

    netManager.SendSmart(writer, Op.AI_TRANSFORM_SNAPSHOT);
    NetPacketPool.ReturnWriter(writer);
}

```

#### 2. 增量同步（Delta Synchronization）

**用于**：玩家位置、动画参数

**特点**：- 只发送变化的数据

- 高频更新（50-60Hz）

- 使用插值平滑显示

**示例**：```csharp
// 位置增量更新
public void SendPositionUpdate()
{
    if (Vector3.Distance(lastPos, currentPos) < 0.01f) return;  // 去抖

    var writer = NetPacketPool.GetWriter();
    writer.Put((byte)Op.POSITION_UPDATE);
    writer.Put(playerID);
    writer.PutVector3(currentPos);
    writer.PutQuaternion(currentRot);
    writer.Put(Time.time);  // 时间戳

    netManager.SendSmart(writer, Op.POSITION_UPDATE);
    NetPacketPool.ReturnWriter(writer);

    lastPos = currentPos;
}

```

#### 3. 事件同步（Event Synchronization）

**用于**：射击、投掷、拾取、伤害

**特点**：- 一次性事件

- 可靠传输（ReliableOrdered）

- 包含完整事件信息

**示例**：```csharp

// 发送玩家位置更新
public void SendPositionUpdate(Vector3 position, Quaternion rotation)
{

    try
    {
        writer.Put((byte)Op.POSITION_UPDATE);

    }
}

## 使用的设计模式

#### 1. 单例模式（Singleton Pattern）

**应用**：- `NetService.Instance`

- `COOPManager`（静态类）

- `SteamLobbyManager.Instance`

- `SteamP2PManager.Instance`

- `DeferedRunner.Instance`

**优点**：- 全局唯一实例

- 易于访问

- 自动初始化

**示例**：```csharp

    public static NetService Instance;
    
    public void OnEnable()

        Instance = this;
    }
}

// 使用

#### 2. 对象池模式（Object Pool Pattern）

**应用**：- `NetPacketPool`: NetDataWriter对象池

- 特效对象池（枪口火光、抛壳粒子）

**优点**：- 减少GC压力

- 提高性能

- 复用对象

**示例**：```csharp
public static class NetPacketPool
{
    private static readonly ConcurrentBag<NetDataWriter> _pool = new();
    private const int MaxPoolSize = 100;

    public static NetDataWriter GetWriter()
    {
        if (_pool.TryTake(out var writer))
        {
            writer.Reset();
            return writer;
        }
        return new NetDataWriter();
    }

    public static void ReturnWriter(NetDataWriter writer)
    {
        if (_pool.Count < MaxPoolSize)
        {
            writer.Reset();
            _pool.Add(writer);
        }
    }
}

```

#### 3. 观察者模式（Observer Pattern）

**应用**：- 网络事件回调（INetEventListener）

- Unity事件系统（UnityAction）

- Steam回调（Callback<T>）

**优点**：- 解耦发送者和接收者

- 支持多个观察者

- 易于扩展

**示例**：```csharp

#### 4. 策略模式（Strategy Pattern）

**应用**：- 传输模式选择（Direct/SteamP2P）

- 优先级策略（PacketPriority）

- 同步策略（快照/增量/事件）

**优点**：- 灵活切换策略

- 易于添加新策略

- 符合开闭原则

**示例**：```csharp
public enum NetworkTransportMode
{
    Direct,      // 直连UDP
    SteamP2P     // Steam P2P
}

public void StartNetwork(bool isServer, NetworkTransportMode mode)
{
    TransportMode = mode;

    switch (mode)
    {
        case NetworkTransportMode.Direct:
            InitDirectTransport();
            break;
        case NetworkTransportMode.SteamP2P:
            InitSteamP2PTransport();
            break;
    }
}

```

#### 5. 代理模式（Proxy Pattern）

**应用**：- Steam P2P代理UDP Socket

- 客户端代理本地操作

**优点**：- 透明替换底层实现

- 添加额外功能（如日志、缓存）

- 控制访问

**示例**：```csharp
// Steam P2P代理Socket发送
[HarmonyPatch(typeof(Socket), "SendTo")]
[HarmonyPrefix]
static bool Prefix(Socket __instance, byte[] buffer, int offset, int size, SocketFlags socketFlags, EndPoint remoteEP)
{
    // 检测虚拟IP（10.255.x.x）
    if (IsVirtualEndPoint(remoteEP))
    {
        // 转换为SteamID
        var steamId = SteamEndPointMapper.GetSteamID(remoteEP);

        // 使用Steam P2P发送
        SteamP2PManager.Instance.SendPacket(steamID, buffer, offset, size);

        // 跳过原Socket发送
        return false;
    }

    // 非虚拟IP，执行原Socket发送
    return true;
}

```


#### 6. 拦截器模式（Interceptor Pattern）

**应用**：- Harmony补丁系统

- 所有Prefix/Postfix补丁

**优点**：- 非侵入式修改

- 可以拦截任意方法

- 支持多个拦截器

**示例**：```csharp
[HarmonyPatch(typeof(CharacterItemControl), "PickupItem")]
[HarmonyPrefix]
static bool Prefix(CharacterItemControl __instance, Item item)
{
    if (!networkStarted) return true;  // 单机模式，执行原方法

    // 联机模式：拦截拾取，改为向主机请求
    SendPickupRequest(item);
    return false;  // 跳过原方法
}

```

#### 7. 工厂模式（Factory Pattern）

**应用**：- 远程玩家克隆创建

- AI生成

- 物品生成

**优点**：- 封装创建逻辑

- 统一创建接口

- 易于扩展

**示例**：```csharp
public static GameObject CreateRemotePlayer(PlayerStatus status)
{
    // 克隆本地玩家模型
    var localPlayer = FindLocalPlayer();
    var remotePlayer = Instantiate(localPlayer);

    // 移除本地玩家组件
    Destroy(remotePlayer.GetComponent<PlayerInput>());
    Destroy(remotePlayer.GetComponent<PlayerController>());

    // 添加网络组件
    remotePlayer.AddComponent<NetInterpolator>();
    remotePlayer.AddComponent<AnimParamInterpolator>();
    remotePlayer.AddComponent<AutoRequestHealthBar>();

    // 应用玩家状态
    ApplyPlayerStatus(remotePlayer, status);

    return remotePlayer;
}

```

#### 8. 命令模式（Command Pattern）

**应用**：- 网络操作码（Op枚举）

- 每个操作码对应一个命令

**优点**：- 解耦发送者和接收者

- 易于添加新命令

- 支持命令队列

**示例**：```csharp
public void HandleNetworkMessage(NetPacketReader reader)
{
    var op = (Op)reader.GetByte();

    switch (op)
    {
        case Op.POSITION_UPDATE:
            HandlePositionUpdate(reader);
            break;
        case Op.FIRE_EVENT:
            HandleFireEvent(reader);
            break;
        case Op.ITEM_SPAWN:
            HandleItemSpawn(reader);
            break;
        // ... 更多命令
    }
}

```

#### 9. 组件模式（Component Pattern）

**应用**：- Unity MonoBehaviour组件

- 网络标记组件（NetAiTag, NetDropTag等）

- 插值器组件（NetInterpolator, AnimParamInterpolator）

**优点**：- 模块化设计

- 易于组合

- 自动管理生命周期

**示例**：```csharp
// 为远程玩家添加多个组件
var remotePlayer = CreateRemotePlayer();

remotePlayer.AddComponent<AnimParamInterpolator>();

remotePlayer.AddComponent<HoldVisualBinder>();

```

#### 10. 状态模式（State Pattern）

**应用**：- 网络连接状态

- 玩家状态（PlayerStatus）

- 场景加载状态

**优点**：- 清晰的状态转换

- 易于添加新状态

- 避免复杂的if-else

**示例**：```csharp
public enum ConnectionState
{
    Disconnected,
    Connecting,
    Connected,
    Disconnecting
}

private ConnectionState _state = ConnectionState.Disconnected;

public void Update()
{
    switch (_state)
    {
        case ConnectionState.Disconnected:
            // 等待连接
            break;
        case ConnectionState.Connecting:
            // 连接中
            if (IsConnected())
            {
                _state = ConnectionState.Connected;
                OnConnected();
            }
            break;
        case ConnectionState.Connected:
            // 已连接，处理网络消息
            ProcessNetworkMessages();
            break;
        case ConnectionState.Disconnecting:
            // 断开连接中
            if (IsDisconnected())
            {
                _state = ConnectionState.Disconnected;
                OnDisconnected();
            }
            break;
    }
}

```

## 技术亮点

### 1. Fika架构插值系统

完全参考Fika项目实现的高级网络插值系统：

- **时间轴系统**：独立的本地时间轴，支持动态时间缩放

- **追赶/减速机制**：自动调整播放速度，保持同步

- **动态延迟调整**：根据网络质量自动优化缓冲延迟

- **EMA平滑**：使用指数移动平均减少网络抖动

- **异常跳变检测**：自动检测并处理瞬移（>6米）

### 2. 智能网络传输

根据数据类型自动选择最优传输方式：

- **Critical**：投票、伤害 → ReliableOrdered（必须送达且有序）

- **Important**：血量、装备 → ReliableSequenced（必须送达，只保留最新）

- **Normal**：NPC、物品 → ReliableUnordered（必须送达，无序）

- **Frequent**：位置、动画 → Unreliable（可丢弃，高频）

### 3. 数据压缩优化

高效的数据压缩算法：

- **位置压缩**：Vector3从24字节压缩到12字节（50%节省）

- **方向压缩**：方向向量从12字节压缩到4字节（67%节省）

- **标志压缩**：4个bool从4字节压缩到1字节（75%节省）

- **总体带宽节省**：约50-70%

### 4. 主机权威架构

确保游戏状态一致性和公平性：

- **伤害结算**：主机权威计算伤害，防止作弊

- **物品生成**：主机分配唯一ID，防止重复

- **AI行为**：主机控制AI，客户端只显示

- **场景切换**：主机协调所有玩家同步加载

### 5. 非侵入式修改

使用HarmonyLib实现运行时代码注入：

- **无需修改游戏文件**：保持游戏原始文件完整

- **动态补丁**：运行时注入代码

- **易于维护**：补丁独立于游戏代码

- **兼容性好**：支持游戏更新

### 6. Steam P2P集成

透明的Steam P2P网络传输：

- **虚拟IP映射**：10.255.x.x ↔ CSteamID

- **NAT穿透**：自动握手和中继

- **Lobby系统**：完整的房间管理

- **密码保护**：SHA256哈希验证

### 7. 性能优化

多层次的性能优化：

- **对象池**：NetDataWriter对象池，减少GC

- **二分查找**：大缓冲区使用O(log n)查找

- **组件缓存**：缓存Animator、Transform等组件

- **去抖限流**：防止高频操作

- **异步加载**：使用UniTask异步加载资源

### 8. 完善的错误处理

多层次的错误处理机制：

- **Try-Catch保护**：防止崩溃

- **空值检查**：严格的null检查

- **降级策略**：失败时使用兜底方案

- **详细日志**：便于调试和问题定位
