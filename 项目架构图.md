    Server->>P1: 房间创建成功
    
    Note over P1,Game: 2. 玩家加入
    P2->>Server: 连接请求<br/>Connect(IP, Port)
    Server->>P2: 连接成功<br/>OnPeerConnected
    Server->>P1: 通知新玩家加入
    P2->>Server: 发送玩家信息<br/>ClientStatus
    Server->>P1: 同步玩家信息
    
    Note over P1,Game: 3. 进入游戏
    P1->>Server: 开始游戏
    Server->>P2: 同步游戏状态
    Server->>Game: 生成玩家角色
    Game->>P1: 本地玩家就绪
    Game->>P2: 远程玩家就绪
    
    Note over P1,Game: 4. 游戏进行中
    loop 实时同步
        P1->>Server: 位置/动作更新
        Server->>P2: 转发P1数据
        P2->>Server: 位置/动作更新
        Server->>P1: 转发P2数据
        
        Server->>P1: AI状态同步
        Server->>P2: AI状态同步
        
        P2->>Server: 伤害报告
        Server->>Server: 权威计算
        Server->>P1: 伤害结果
        Server->>P2: 伤害结果
    end
    
    Note over P1,Game: 5. 场景切换
    P1->>Server: 发起投票<br/>VoteRequest
    Server->>P1: VoteStart
    Server->>P2: VoteStart
    P1->>Server: VoteCast(ready)
    P2->>Server: VoteCast(ready)
    Server->>P1: VoteBeginLoad
    Server->>P2: VoteBeginLoad
    P1->>P1: 加载新场景
    P2->>P2: 加载新场景
    
    Note over P1,Game: 6. 游戏结束
    P2->>Server: 断开连接
    Server->>P1: 玩家离开通知
    P1->>Server: 关闭服务器
    Server->>Server: 清理资源

## 20. 总结与说明

### 架构特点

1. **分层架构**
   - 入口层：模组加载和初始化
   - 服务层：核心网络和管理服务
   - 业务层：具体游戏功能模块
   - 网络层：数据传输和RPC通信
   - 补丁层：游戏代码注入

2. **核心技术**
   - Harmony代码注入：无侵入式修改游戏逻辑
   - LiteNetLib：高性能UDP网络传输
   - Steam P2P：Steam平台P2P通信
   - 混合RPC系统：灵活的远程调用机制
   - Fika插值：平滑的位置同步

3. **性能优化**
   - 数据压缩：Vector3/Quaternion压缩
   - 对象池：减少GC压力
   - 多通道：避免队头阻塞
   - 智能发送：自动选择最优传输方式
   - 增量更新：只发送变化的数据

4. **可靠性保障**
   - 主机权威：防止作弊
   - 数据验证：确保数据合法性
   - 错误处理：完善的异常捕获
   - 自动重连：网络断线恢复
   - 状态同步：保证一致性

### 使用建议

1. **开发者**
   - 从整体架构图开始理解项目结构
   - 深入学习各模块的详细流程
   - 参考RPC通信架构实现新功能
   - 遵循现有的设计模式

2. **维护者**
   - 关注数据流向图理解数据传递
   - 使用操作码分类图查找相关功能
   - 参考错误处理架构完善异常处理
   - 定期检查性能优化效果

3. **贡献者**
   - 理解补丁系统架构再添加新补丁
   - 遵循文件结构树组织代码
   - 参考关键类关系图设计新类
   - 应用设计模式保持代码质量
