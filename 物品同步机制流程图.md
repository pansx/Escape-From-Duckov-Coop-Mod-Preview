# 物品同步机制流程图

## 概述

这个mod的物品同步采用**客户端-服务器架构**，所有物品操作都需要经过主机验证和广播。

## 核心组件

### 1. 消息类型 (Op.cs)
- `ITEM_DROP_REQUEST` (12) - 客户端请求丢弃物品
- `ITEM_SPAWN` (13) - 主机广播物品生成
- `ITEM_PICKUP_REQUEST` (14) - 客户端请求拾取物品
- `ITEM_DESPAWN` (15) - 主机广播物品消失
- `LOOT_REQ_OPEN` (250) - 客户端请求容器快照
- `LOOT_STATE` (251) - 主机下发容器快照
- `LOOT_REQ_PUT` (252) - 客户端请求放入物品
- `LOOT_REQ_TAKE` (253) - 客户端请求取出物品
- `LOOT_PUT_OK` (254) - 主机确认放入成功
- `LOOT_TAKE_OK` (255) - 主机确认取出成功
- `LOOT_DENY` (249) - 主机拒绝操作
- `LOOT_REQ_SPLIT` (239) - 客户端请求拆分物品
- `LOOT_REQ_SLOT_PLUG` (209) - 客户端请求装配件
- `LOOT_REQ_SLOT_UNPLUG` (208) - 客户端请求拆配件

### 2. 核心类
- `LootNet.cs` - 战利品箱同步核心逻辑
- `ItemPatch.cs` - 物品拾取/添加拦截
- `ItemUtilitiesPatch.cs` - 物品工具方法拦截
- `SlotPatch.cs` - 装备槽位操作拦截

```csharp
public void Server_SendLootboxState(NetPeer toPeer, Inventory inv)
{
    var w = new NetDataWriter();
    w.Put((byte)Op.LOOT_STATE);
    LootManager.Instance.PutLootId(w, inv);
    
    var capacity = inv.Capacity;
    w.Put(capacity);
    
    // 统计非空格子
    var count = 0;
    var content = inv.Content;
    for (var i = 0; i < content.Count; ++i)
        if (content[i] != null) count++;
    w.Put(count);
    
    // 逐个写物品
    for (var i = 0; i < content.Count; ++i)
    {
        var it = content[i];
        if (it == null) continue;
        w.Put(i);  // 位置
        ItemTool.WriteItemSnapshot(w, it);  // 物品快照
    }
    
    if (toPeer != null) 
        toPeer.Send(w, DeliveryMethod.ReliableOrdered);
    else 
        CoopTool.BroadcastReliable(w);
}
```

```csharp
private System.Collections.IEnumerator Client_ApplyLootboxStateCoroutine(
    Inventory inv, int capacity, List<(int pos, ItemSnapshot snap)> itemData)
{
    _applyingLootState = true;
    try
    {
        inv.SetCapacity(capacity);
        
        // 删除旧物品（每5个yield一次）
        int deleteCount = 0;
        for (var i = inv.Content.Count - 1; i >= 0; --i)
        {
            Item removed;
            inv.RemoveAt(i, out removed);
            if (removed) Object.Destroy(removed.gameObject);
            
            deleteCount++;
            if (deleteCount % 5 == 0) yield return null;
        }
        
        // 添加新物品（每3个yield一次）
        int addCount = 0;
        foreach (var (pos, snap) in itemData)
        {
            var item = ItemTool.BuildItemFromSnapshot(snap);
            if (item == null) continue;
            inv.AddAt(item, pos);
            
            addCount++;
            if (addCount % 3 == 0) yield return null;
        }
    }
    finally
    {
        _applyingLootState = false;
    }
}
```

```csharp
            return;

    w.Reset();

    LootManager.Instance.PutLootId(w, lootInv);
```

```csharp
public void Server_HandleLootPutRequest(NetPeer peer, NetPacketReader r)
{
    // 读取参数
    var scene = r.GetInt();
    var posKey = r.GetInt();
    var iid = r.GetInt();
    var lootUid = r.GetInt();
    var prefer = r.GetInt();
    var token = r.GetUInt();
    
    // 解析快照
    ItemSnapshot snap = ItemTool.ReadItemSnapshot(r);
    
    // 定位容器
    Inventory inv;
    if (!LootManager.Instance.TryResolveLootById(scene, posKey, iid, out inv))
    {
        Server_SendLootDeny(peer, "no_inv");
        return;
    }
    
    // 重建物品
    var item = ItemTool.BuildItemFromSnapshot(snap);
    
    // 添加到容器
    _serverApplyingLoot = true;
    var ok = inv.AddAndMerge(item, prefer);
    _serverApplyingLoot = false;
    
    if (!ok)
    {
        Server_SendLootDeny(peer, "add_fail");
        return;
    }
    
    // 发送确认
    var ack = new NetDataWriter();
    ack.Put((byte)Op.LOOT_PUT_OK);
    ack.Put(token);
    peer.Send(ack, DeliveryMethod.ReliableOrdered);
    
    // 广播新状态
    Server_SendLootboxState(null, inv);
}
```

```csharp
public void Client_OnLootPutOk(NetPacketReader r)
{
    var token = r.GetUInt();
    
    // 查找待删除的物品
    if (_cliPendingPut.TryGetValue(token, out var localItem) && localItem)
    {
        _cliPendingPut.Remove(token);
        
        // 删除本地物品
        try
        {
            localItem.Detach();
            Object.Destroy(localItem.gameObject);
        }
        catch { }
        
        // 清理重复引用
        var stale = new List<uint>();
        foreach (var kv in _cliPendingPut)
            if (!kv.Value || ReferenceEquals(kv.Value, localItem))
                stale.Add(kv.Key);
        foreach (var k in stale) 
            _cliPendingPut.Remove(k);
    }
}
```

```csharp
public void Server_HandleLootTakeRequest(NetPeer peer, NetPacketReader r)
{
    // 读取参数
    var scene = r.GetInt();
    var posKey = r.GetInt();
    var iid = r.GetInt();
    var lootUid = r.GetInt();
    var position = r.GetInt();
    var token = r.GetUInt();
    
    // 定位容器
    Inventory inv;
    if (!LootManager.Instance.TryResolveLootById(scene, posKey, iid, out inv))
    {
        Server_SendLootDeny(peer, "no_inv");
        return;
    }
    
    // 从容器移除
    _serverApplyingLoot = true;
    Item removed = null;
    var ok = inv.RemoveAt(position, out removed);
    _serverApplyingLoot = false;
    
    if (!ok || removed == null)
    {
        Server_SendLootDeny(peer, "rm_fail");
        Server_SendLootboxState(peer, inv);  // 刷新客户端
        return;
    }
    
    // 发送物品快照
    var wCli = new NetDataWriter();
    wCli.Put((byte)Op.LOOT_TAKE_OK);
    wCli.Put(token);
    ItemTool.WriteItemSnapshot(wCli, removed);
    peer.Send(wCli, DeliveryMethod.ReliableOrdered);
    
    // 销毁主机端物品
```

```csharp
{
    var token = r.GetUInt();
    
    // 1) 重建物品
    var snap = ItemTool.ReadItemSnapshot(r);
    var newItem = ItemTool.BuildItemFromSnapshot(snap);
    
    // 2) 查找目的地
    PendingTakeDest dest;
    if (LootManager.Instance._cliPendingTake.TryGetValue(token, out dest))
        LootManager.Instance._cliPendingTake.Remove(token);

    if (dest.slot != null)
    {
        Item victim = dest.slot.Content;
        if (victim != null)
        {
            // 交换：先PUT旧物品，成功后再装备新物品
            _cliSwapByVictim[victim] = (newItem, null, -1, dest.slot);
            Client_SendLootPutRequest(srcLoot, victim, dest.srcPos);
            return;

        // 直接装备
        if (dest.slot.Plug(newItem, out _))
            return;
        
        // 失败：放回容器
        PutBackToSource_NoTrack(newItem, dest);
        return;
    }
    
    // 4) 目标是背包
    if (dest.inv != null)
    {
        Item victim = dest.inv.GetItemAt(dest.pos);
        if (victim != null)
        {
            // 交换：先PUT旧物品
            _cliSwapByVictim[victim] = (newItem, dest.inv, dest.pos, null);
            Client_SendLootPutRequest(srcLoot, victim, dest.srcPos);
            return;
        }
        
        // 尝试放入
        if (dest.inv.AddAt(newItem, dest.pos)) return;
        if (dest.inv.AddAndMerge(newItem, dest.pos)) return;
        
        // 失败：放回容器
        PutBackToSource_NoTrack(newItem, dest);
        return;
    }
    
    // 5) 未指定目的地：尝试主背包
    var backpack = LevelManager.Instance?.MainCharacter?.CharacterItem?.Inventory;
    if (backpack != null)
    {
        if (backpack.AddAndMerge(newItem)) return;
        if (backpack.AddItem(newItem)) return;
```

```csharp
public static async UniTask Server_DoSplitAsync(Inventory inv, int srcPos, 
                                                 int count, int prefer)
{
    var srcItem = inv.GetItemAt(srcPos);
    if (!srcItem) return;
    
    // 减少源堆数量
    srcItem.StackCount -= count;
    
    // 创建新堆
    var newItem = await srcItem.Split(count);
    if (!newItem) return;
    
    // 找落位
    if (prefer < 0 || prefer >= inv.Capacity || inv.GetItemAt(prefer) != null)
        prefer = inv.GetFirstEmptyPosition();
    
    // 添加到容器
    if (prefer >= 0)
        inv.AddAt(newItem, prefer);
    else
        inv.AddAndMerge(newItem);
    
    // 广播新状态
    COOPManager.LootNet.Server_SendLootboxState(null, inv);
}
```

```csharp
public static void WriteItemSnapshot(NetDataWriter w, Item item)
{
    // 基础属性
    w.Put(item.ItemType.Id);
    w.Put(item.StackCount);
    w.Put(item.Durability);
    w.Put(item.DurabilityLoss);
    w.Put(item.Inspected);
    
    // 附件槽位
    var slots = new List<(string, ItemSnapshot)>();
    if (item.Slots != null)
    {
        foreach (var slot in item.Slots.AllSlots)
        {
            if (slot.Content != null)
            {
                var childSnap = CreateSnapshot(slot.Content);  // 递归
                slots.Add((slot.Key, childSnap));
            }
        }
    }
    w.Put(slots.Count);
    foreach (var (key, snap) in slots)
    {
        w.Put(key);
        WriteItemSnapshotRecursive(w, snap);  // 递归写入
    }
    
    // 容器内容
    var inventory = new List<ItemSnapshot>();
    if (item.Inventory != null)
    {
        foreach (var subItem in item.Inventory.Content)
        {
            if (subItem != null)
            {
                var subSnap = CreateSnapshot(subItem);  // 递归
                inventory.Add(subSnap);
            }
        }
    }
    w.Put(inventory.Count);
    foreach (var snap in inventory)
    {
        WriteItemSnapshotRecursive(w, snap);  // 递归写入
    }
}
```

```csharp
public static ItemSnapshot ReadItemSnapshot(NetDataReader r)
{
    var snap = new ItemSnapshot();
    
    // 基础属性
    snap.typeId = r.GetInt();
    snap.stack = r.GetInt();
    snap.durability = r.GetFloat();
    snap.durabilityLoss = r.GetFloat();
    snap.inspected = r.GetBool();
    
    // 附件槽位
    var slotCount = r.GetInt();
    snap.slots = new List<(string, ItemSnapshot)>(slotCount);
    for (int i = 0; i < slotCount; i++)
    {
        var key = r.GetString();
        var child = ReadItemSnapshot(r);  // 递归
        snap.slots.Add((key, child));
    }
    
    // 容器内容
    var invCount = r.GetInt();
    snap.inventory = new List<ItemSnapshot>(invCount);
    for (int i = 0; i < invCount; i++)
    {
        var item = ReadItemSnapshot(r);  // 递归
        snap.inventory.Add(item);
    }
    
    return snap;
}

public static Item BuildItemFromSnapshot(ItemSnapshot snap)
{
    // 创建物品
    var item = ItemDatabase.Instance.CreateItem(snap.typeId);
    if (!item) return null;
    
    // 设置属性
    item.StackCount = snap.stack;
    item.Durability = snap.durability;
    item.DurabilityLoss = snap.durabilityLoss;
    item.Inspected = snap.inspected;
    
    // 重建附件
    if (snap.slots != null)
    {
        foreach (var (key, childSnap) in snap.slots)
        {
            var child = BuildItemFromSnapshot(childSnap);  // 递归
            if (child)
            {
                var slot = item.Slots?.GetSlot(key);
                slot?.Plug(child, out _);
            }
        }
    }
    
    // 重建容器内容
    if (snap.inventory != null && item.Inventory != null)
    {
        foreach (var subSnap in snap.inventory)
        {
            var subItem = BuildItemFromSnapshot(subSnap);  // 递归
            if (subItem)
                item.Inventory.AddItem(subItem);
        }
    }
    
    return item;
}
```


## 四、同步机制核心设计

### 4.1 客户端-服务器架构

```
┌─────────────────────────────────────────────────────────────────┐
│                   架构设计原则                                    │
└─────────────────────────────────────────────────────────────────┘

1. 权威服务器模式
   - 主机是唯一的权威源
   - 所有物品操作必须经过主机验证
   - 客户端只能发送请求，不能直接修改

2. 乐观更新 + 回滚
   - 客户端拾取：立即销毁地面物体（乐观）
   - 客户端放入：等待主机确认后才删除本地物品
   - 失败时：主机发送DENY，客户端回滚或刷新

3. 快照同步
   - 主机维护容器的权威状态
   - 客户端请求时下发完整快照
   - 任何修改后广播新快照给所有客户端

4. Token机制
   - 客户端生成递增token标识请求
   - 主机回复时携带token，客户端匹配处理
   - 用于异步请求-响应的关联

5. 防重机制
   - _cliPendingPut: 防止同一物品重复PUT
   - _cliPendingTake: 记录TAKE的目的地
   - _cliSwapByVictim: 处理交换操作的中间状态
```

```
      - 查找 _cliSwapByVictim[B]
      - 删除本地的B
```

## 七、总结

### 7.1 设计亮点

1. **权威服务器模式**: 确保所有客户端状态一致，主机是唯一真相源
2. **快照同步**: 简化同步逻辑，每次修改后广播完整状态
3. **Token机制**: 优雅处理异步请求-响应关联
4. **交换逻辑**: 巧妙处理复杂的物品交换场景
5. **性能优化**: 协程分帧、延迟广播、静音窗口等多重优化
6. **容错机制**: 失败回滚、防重检查、缓存机制

### 7.2 关键技术点

- **Harmony Patch**: 无侵入式拦截游戏原生逻辑
- **递归序列化**: 完整保存物品树结构（附件、容器内容）
- **状态标志**: 防止循环触发和重复广播
- **UID定位**: 解决场景切换后的容器定位问题
- **分帧处理**: 避免大量物品同步时的性能问题

### 8.6 客户端捡尸空墓碑问题

#### 问题原因

```
客户端死亡
    ↓
生成墓碑，注册 _cliLootByUid[lootUid] = inv ✅
    ↓
客户端撤退（场景切换）
    ↓
❌ _cliLootByUid 被清空（字典不跨场景持久化）
    ↓
客户端重新进入场景
    ↓
墓碑物理对象还在（Unity场景持久化）
    ↓
但 _cliLootByUid[lootUid] 已经不存在 ❌
    ↓
客户端打开墓碑时无法通过 lootUid 找到 Inventory
    ↓
❌ 显示为空墓碑
```

#### 解决方案对比

| 方案 | 实现方式 | 优点 | 缺点 |
|------|---------|------|------|
| 持久化索引 | 静态字典保存lootUid→位置 | 健壮，跨场景有效 | 需要场景加载时恢复 |
| GameObject标记 | 墓碑上添加LootUidTag组件 | 简单，改动最小 | 依赖Unity持久化 |
| 主机重新广播 | 客户端重进时请求同步 | 容错性强 | 增加网络开销 |
| 增强位置查找 | 扩大搜索半径，按类型过滤 | 兜底机制 | 不能根本解决 |

**推荐方案**: GameObject标记 + 持久化索引

### 8.12 墓碑系统常见问题

#### 问题1: 客户端捡尸空墓碑

**现象**: 客户端撤退后重新进入场景，墓碑显示为空

**原因**: `_cliLootByUid` 索引在场景切换时丢失

**解决**: 添加 `LootUidTag` 组件 + 场景加载时恢复索引

**详见**: 客户端捡尸空墓碑问题分析.md

#### 问题2: 墓碑位置不准确

**现象**: 墓碑生成位置与死亡位置有偏差

**原因**: 
- 网络延迟导致位置同步不及时
- 客户端和主机的物理模拟差异

**解决**: 
- 使用死亡时的精确位置
- 主机权威决定墓碑位置

#### 问题3: 墓碑重复生成

**现象**: 同一个死亡事件生成多个墓碑

**原因**: 
- 死亡事件被多次触发
- 网络消息重复接收

**解决**: 
- 使用 `lootUid` 去重
- 检查墓碑是否已存在

#### 问题4: 墓碑物品未标记为未鉴定

**现象**: 打开墓碑时直接看到物品属性

**原因**: 
- `NeedInspection` 标记未设置
- `Inspected` 标记未清除

**解决**: 
```csharp
inv.NeedInspection = true;
for (var i = 0; i < inv.Content.Count; ++i)
{
    var it = inv.GetItemAt(i);
    if (it) it.Inspected = false;
}
```

### 8.13 墓碑系统总结

#### 核心机制

1. **物品保留**: 客户端死亡时阻止物品掉落和销毁
2. **主机生成**: 主机检测死亡后生成墓碑并分配稳定ID
3. **广播同步**: 主机广播墓碑生成消息给所有客户端
4. **索引管理**: 主机和客户端分别维护 `lootUid → Inventory` 映射
5. **内容同步**: 客户端打开墓碑时请求主机下发内容快照

#### 关键数据

- **aiId**: 死者的角色ID，用于识别墓碑所属者
- **lootUid**: 墓碑的稳定ID，用于快速定位和跨场景持久化
- **position/rotation**: 墓碑的位置和旋转
- **Inventory**: 墓碑的容器对象，存储物品

#### 设计优势

1. **权威服务器**: 主机控制墓碑生成和内容，防止作弊
2. **稳定ID**: 使用 `lootUid` 解决场景切换后的定位问题
3. **分帧处理**: 避免瞬间卡顿，提升性能
4. **物品保留**: 客户端死亡不掉落物品，提升游戏体验
5. **未鉴定标记**: 增加游戏难度和真实感

#### 待改进点

1. **索引持久化**: 需要实现跨场景的索引恢复机制
2. **墓碑清理**: 需要实现墓碑的自动清理机制
3. **容错机制**: 需要增强位置查找的容错性
4. **网络优化**: 可以考虑延迟广播或批量广播

### 9.5 完整流程总结

#### 1. 物品拾取流程
```
玩家拾取 → Patch拦截 → 本地销毁 → 发送PICKUP_REQUEST 
→ 主机验证 → 主机销毁 → 广播DESPAWN → 所有客户端同步删除
```

#### 2. 战利品箱操作流程
```
玩家操作 → Patch拦截 → 生成token → 发送请求(PUT/TAKE/SPLIT/PLUG/UNPLUG)
→ 主机验证 → 主机执行 → 发送确认(OK/DENY) → 客户端处理响应
→ 主机广播LOOT_STATE → 所有客户端应用快照
```

#### 3. 玩家死亡墓碑流程
```
玩家死亡 → Patch阻止掉落 → 上报死亡 → 主机生成墓碑 → 分配lootUid
→ 标记未鉴定 → 广播DEAD_LOOT_SPAWN → 客户端生成墓碑 → 注册索引
→ 请求内容 → 主机发送LOOT_STATE → 客户端显示墓碑
```

### 9.6 关键技术点总结

1. **权威服务器模式**: 主机是唯一真相源，所有操作需主机验证
2. **Token机制**: 异步请求-响应关联，支持并发操作
3. **快照同步**: 每次修改后广播完整状态，简化同步逻辑
4. **递归序列化**: 完整保存物品树结构（附件、容器内容）
5. **稳定ID系统**: 使用lootUid解决场景切换后的定位问题
6. **分帧处理**: 协程分帧避免卡顿，提升性能
7. **状态标志**: 防止循环触发和重复广播
8. **交换逻辑**: 巧妙处理复杂的物品交换场景
9. **物品保留**: 客户端死亡不掉落物品，提升体验
